# Read-only essentials: screening candidates

Five complete inert skill packages are retained here at version `0.1.0`:
inbox briefing, calendar briefing, file discovery, public GitHub pull request
review, and web research. `List`, `Files(key)` and `Archive(key)` expose their
complete sources. Archives are deterministic, asset inventories are SHA-256
pinned, and tests use the existing package-closure verifier.

These are **authored screening candidates**. They are not approved, signed,
provenance-verified, admitted, installed, provider-connected, model-evaluated or
workflow-qualified. `operator_asserted` is the manifest format's trust class; it
is not a statement that a user approved or authenticated these packages.
`publication.status=screening` is supported by the existing package validator
and deliberately differs from `approved`.

Each `assets/requirements.json` uses a new explicitly draft documentation format.
The `draft/*@0.1.0` capability references specify intended read-only semantics and
budgets. They supply **no executable composition, provider tool/input/output
schema, implementation binding or account grant**. A client must stop until all
requirements have been designed, reviewed and mapped to current authorized,
schema-validated tools. The existing maintained inbox skills remain independent;
these candidates do not replace or change their immutable versions.

A passing package test proves retained bytes, inventory and screening labels. It
does not demonstrate that Zati can run these workflows or justify a Featured
badge. See `docs/guides/directory-workflows.md` for setup and qualification work.
