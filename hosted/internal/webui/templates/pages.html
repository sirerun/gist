Start with the Go library

Index content from sources you control, then retrieve relevant context within a token budget. An in-memory store works out of the box.

go get github.com/sirerun/gist
import "github.com/sirerun/gist"

g, err := gist.New()
if err != nil {
    return err
}
defer g.Close()

_, err = g.Index(ctx, content,
    gist.WithSource("my-guide"))
if err != nil {
    return err
}
results, err := g.Search(ctx, "authentication flow",
    gist.WithBudget(4000))

For catalog publication, immutable packages, discovery, and preparation, use the separate github.com/sirerun/gist/catalog packages. The root text-search library and catalog packages serve different integration needs.

Gist public API and MCP discovery

Free public discovery requires no sign-in or API key. Start with the API entry point and OpenAPI reference, or add the public MCP server below. See the agent guide, official CLI and access details.

No sign-in is required for public directory metadata. Add this Streamable HTTP endpoint to a compatible client:

https://gist.sire.run/directory/mcp

Five tools search apps, inspect connectors, explain authorization and export descriptors: gist_directory_apps, gist_directory_search, gist_directory_get, gist_directory_authorization, gist_directory_export. Search the full app catalog with gist_directory_apps, then request gist_directory_authorization with an exact app slug and version: 2 for reviewed MCP and direct API routes with explicit coverage gaps. Use GET /api/directory/authorization?id=... or gist_directory_authorization with an exact connector ID for provider-sourced setup steps, prerequisites and documentation. Guides report documented or needs_research; documented instructions have not been tested with your account. Exports describe setup requirements. Your client must independently admit tools, connect accounts and execute.

REST: GET /api/directory?q=calendar. Embedded Go: github.com/sirerun/gist/catalog/directory. Browse an evolving catalog; each client determines which integrations it supports and can connect to.

Connect your AI client

Use the hosted MCP endpoint

Add this remote MCP server URL in a client that supports Streamable HTTP and OAuth authorization:

https://gist.sire.run/mcp
  1. Make sure your GitHub account has access to a Gist workspace. Sign in to Gist to check your enrollment.
  2. Add the URL using your client's remote MCP configuration.
  3. Complete the client's OAuth flow and review the requested access. Website sign-in and authorization of an MCP client are separate steps.
  4. Ask the client to discover relevant artifacts, retrieve the chosen version, and check its requirements.

The stable discovery interface includes gist_discover, gist_get, and gist_resolve. Available tools and authorization flows vary by client.

Before the work begins

Resolve requirements explicitly

A skill describes a reusable workflow and the capabilities it needs. Gist matches those requirements to authorized, versioned bindings. Your client supplies the available connections and checks whether the workflow is ready.

Discover candidates→Get exact packages→Resolve requirements

Missing capabilities or unavailable connections stay visible as unresolved requirements. Finding an artifact does not install a tool, connect an account, or authorize execution.

Keep control in your client

Your client validates inputs, connects provider accounts, asks for user approval, runs tools, and manages retries or recovery. Gist provides catalog content and resolution; it does not execute your workflows.

Discover. Resolve. Use.

Gist is a catalog and context library for AI clients. It helps a client find relevant skills and tools, retrieve complete packages at an exact version, and resolve the capabilities a skill requires.

Skill
A reusable workflow with instructions, supporting assets, and declared requirements.
Tool
A described operation with a schema your client can inspect and validate.
Capability
What a workflow needs to accomplish, such as listing or reading messages.
Binding
The versioned link from a capability to a concrete tool available to your client.

Gist narrows the context your agent receives to relevant content. The number of tokens and model turns saved depends on the workload and integration; it is not a fixed promise.

Open your workspace

  1. Sign in with GitHub. Access is invitation based, so use the GitHub account your operator invited.
  2. Open your workspace. Search by intent or name and filter by artifact kind.
  3. Open an artifact to inspect its version, state, digest, and published metadata.

The public library is open to everyone. Your workspace shows only your authorized artifacts and private integrations. An entry is metadata for your client to inspect; it does not connect an account.

Illustrative workflow

A quieter start to your inbox

Imagine asking Zati for a briefing of unread mail. A maintained skill can describe the briefing and declare the capabilities it needs: list messages and read selected messages.

  1. Gist helps your client discover the relevant skill and retrieve its exact package.
  2. The client checks the requirements against its own admitted mail tools and authorized connection.
  3. You connect your mail account and grant access in the client, if you have not already.
  4. The client reads the permitted messages and prepares the briefing under its own execution policy.
Read only, when the client enforces it.

This example needs message listing and reading. A catalog entry does not grant access to Gmail or provide a connected mail account. Availability depends on your client's implementation and connections.

Bring it to your client

In Zati, use its Services experience and the setup supported by your installed version. Account connections, tool admission, approvals, and workflow execution live there. Browsing Gist does not automatically install or activate a skill in Zati.

Other clients can integrate through the Go library or the authenticated MCP endpoint. Follow the client’s supported authorization and package import workflow.

When something is missing

I cannot sign in
Check that you are using the invited GitHub account. Ask your workspace operator to confirm access. If GitHub returns an error, return to sign-in and start a fresh flow.
My library is empty
No matching records may be published for your workspace. Clear your search and kind filter, then ask your operator about catalog content.
A skill cannot run
Inspect its requirements in your client. An absent binding, missing provider connection, or unsupported tool can prevent execution even when a skill is visible.
The service is unavailable
Try again shortly. Operators can inspect process health and service readiness. First enrollment may leave catalog access unavailable until the configured founder completes sign-in.
