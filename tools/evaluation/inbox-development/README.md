# Closed-menu inbox development conformance cohort

This is a new positive development cohort for the actual maintained inbox skill
and the existing controlled composite-tool fixture. It contains30 explicitly
selected caller-menu requests in **one conservative construction family**.
There is no held-out split, negative coverage, independent30-family sample,
whole-task benchmark, generalization, live Gmail or adoption claim.

The actual fixed catalogue and policy template were exported and committed
first, independently of queries. The thirty-intent menu and exact-hash admission
policy were committed next, before cases or gold. Input-only cases were then
committed before either independent annotation. Freeze files record those exact
commits/hashes. The initial export missing required flags failed and is retained
in `catalog-freeze.json`; the corrected export exited before reading inputs.
No model, preparation attempt, provider or mailbox call was performed by the
authoring/export procedure.

## Files

- `catalog.json`: actual exported shared inventory, including unchanged distractors.
- `task-policy.template.json`: actual maintained pin/caller contract template.
- `caller-menu.json`: thirty independent caller-selected intent strings.
- `task-policy.json`: exact SHA-256 of each menu intent, with every non-intent
  field copied unchanged from the previously frozen trusted template.
- `development.inputs.jsonl`: exact menu text, the same ready fixture, no dependencies
  or scenario transitions. It is not a copy of the older pilot corpus.
- `development.labels.jsonl`: canonical gold only after blind independent
  annotation, reconciliation and independent final checking.
- `manifest.json`: artifact hashes, counts, provenance and current label status.

The policy is an **explicit closed menu**, not a natural-language classifier or
live authority service. Unknown text is not admitted. It does not turn a
similarity score or a gold label into permission. Policy/catalog contents must
not change after observing results to improve measured outcomes.

All cases request the same maintained `zati/inbox-briefing@1.0.0` workflow and
`mail/inbox/read@1.0.0` capability. The real source fixture has one composite
`synthetic/mail-read@1.0.0` tool with `list_unread` and `read_message` operations,
plus its provider/binding/capability contracts. It does not have separate list
and read tools. This differs from Zati's two-role MCP consumer and is not evidence
of Zati compatibility or actual mailbox execution. There are no logical skill
dependencies or local-execution/filesystem requirements.

Twenty-four requests are English and six use straightforward Spanish, French,
Kiswahili, German, Portuguese and Italian wording. These are correlated
paraphrases, not separate task families. A ready environment and explicit caller
admission define positive desired coverage; an arm may still miss retrieval or
abstain. Such outcomes must remain recorded, never edited out or relabelled.

Only preparation context is qualified: exact skill/capability/tool pins, complete
instruction/template/contract bytes, and current authority. No email facts,
completed briefing, actual call savings or task-success improvement follows from
this source conformance cohort. Existing model/resource qualification, source
freeze, scoring admission and independent results review remain separate gates.

## Independent labels

Both annotators froze their original files before comparison. The preserved
`development.labels.author1.jsonl` and `development.labels.author2.jsonl` have
identical core truth on all30 cases: family, exact skill/capability/tool versions,
empty dependencies and desired ready status. Their evidence-class vocabulary
was normalized explicitly to `controlled_inbox_development` (30 metadata
differences, not zero differences across every field). The canonical
`development.labels.jsonl` unions both safety/rubric lists.

The second annotator's locale clause is conditional on separately executing a
briefing: immutable prepared context is not translated, and no briefing execution
is claimed or scored here. Original annotations remain unchanged. Per-ID
reconciliation records bind exact canonical JSONL row bytes including the newline;
the manifest binds complete file hashes. Final independent artifact verification
must pass before any scoring admission. No label or policy is adjusted using
retrieval/model results.
