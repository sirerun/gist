## Exact immutable storage and compatibility domains

For skills, artifact digest hashes original ZIP bytes; manifest digest hashes original manifest bytes; package digest hashes the sorted inventory closure. For other kinds, artifact/document digest hashes the exact original JSON value span. Preserve original raw bytes in a BYTEA-backed publication record/object, independently of JSONB search projections. Metadata for a v2 skill is its full frozen manifest, not the minimal historical package-validator struct. Metadata for each typed artifact is its full original typed document.

Add named artifact/document/package digest and owned-object reference fields to the publication storage/port model. Do not store a non-skill capture digest or inventory digest in a manifest column. Forward-only migration permits absent skill-manifest digest for new non-skill records and retains all existing legacy rows/digests. Catalog reads prefer retained v2 original metadata bytes when present and preserve legacy JSONB behavior for old rows.

Existing internal resolution pins require a generic field named ManifestDigest even for non-skills. An explicit compatibility adapter may project a v2 DocumentDigest into that legacy pin field only for capability/tool/provider/binding typed document metadata; this is a documented legacy document-metadata alias, never a v2 skill-manifest claim. Skill pins keep the true manifest digest. The adapter must fail closed on missing/invalid named evidence, preserve old-record behavior and independently rehash retained typed bytes in compatibility tests. V2 responses and headers expose manifest/package digests only for skills. No blanket v1 read/resolution compatibility claim is made until actual byte/domain regression tests pass. If a frozen response requires a different meaning, stop that projection and record an interface finding rather than altering frozen v1 bytes or inventing a digest.

Taxonomy admission writes its exact edition/document and node projections in the same catalog transaction; edition is not coerced into SemVer. Other descriptors use frozen common SemVer grammar. IDs are bounded to 256 characters, use the frozen lower-case grammar, and reject empty, dot or dot-dot path components. Version/edition strings reject controls/whitespace and @ or slash ambiguity. Exact lookup accepts only single known query parameters, once each; it never fetches a source URI.

## Current authorization and per-kind admission

Use current verified issuer/subject/workspace identity, active maintainer membership, catalog:publish scope, matching current policy generation and active namespace reservation. Registry workspace/publisher/owner come from the current principal, never the envelope. Recheck membership, identity revocation/expiry, policy generation and namespace in the admission transaction and on every replay before returning stored bytes. Lock relevant current policy/membership/identity rows or use an equivalent existing transaction fence so concurrent revocation cannot be bypassed after object upload. Bindings and skill capability references are exact and same-workspace; no fallback or implicit reroute.

Outer tenant/publisher fields and any undeclared typed fields reject. The frozen skill manifest's optional publisher field is source-origin metadata only if it matches a separately trusted import-evidence record; it never supplies the authenticated registry owner. Without that qualified record, reject the field rather than infer identity or rights. Do not rewrite the immutable package to manufacture attribution.

Validate every kind against its own frozen schema and declared semantic checks. JSON Schema compilation uses retained resources/built-in dialects only; deny unretained external references and never fetch a URI during publication. Complete skill closure includes strict manifest schema, provenance/trust, entrypoint/frontmatter, safe unique regular members, media/size/hash inventory and independent limits. Capabilities validate schemas/effects/scopes/cost/timeout/retry/idempotency coherence. Tools verify exact action/version, lifecycle, execution location, destination/credential metadata and retained source capture. Providers verify retained capture and source/rights; a support_state string supplies no execution authority. Binding admission requires exact referenced artifacts, actual retained golden bytes and a qualified offline conformance verifier for the exact adapter revision; five executed corpus cases minimum, verified digest/result/pins, no provider actions. Taxonomies require reviewed edition/attribution/redistribution evidence and unique, acyclic, level-consistent node structure.

Use existing trusted review_records as the server evidence boundary, with an explicit typed evidence structure bound to workspace/kind/id/version and raw artifact digest. Its exact field shape is contracts/registry/v2/admission-evidence.schema.json. It holds retained source bytes, source/digest/time, rights scope, reviewer and, where relevant, exact conformance fixture/executor/result pins. Request JSON cannot set this evidence. Unknown, missing, forged or mismatched evidence denies admission. A qualified configured verifier evaluates retained golden data against exact artifacts, not an unconditional stub or a passed string. Evidence installation is an operator workflow, not a new unauthenticated upload API. Synthetic owned fixtures may qualify source behavior only through an explicit fixture configuration; production defaults deny synthetic evidence. Real Treg/Composio schemas, licenses, accounts, targets and live spending authority stay in their existing gates.

## Durable attempts, replay and physical ownership

Keep the legacy global digest namespace untouched. V2 objects use generated opaque attempt keys v2/<128-bit-random-lowercase-hex>/<artifact-sha256> beneath the configured store root/prefix; clients cannot supply a key. The database binds every key to its workspace and attempt. An immutable create verifies exact size/hash and verifies existing content on retry. Reads verify retained size/digest and fail closed on absence/corruption. File operations remain root-confined and reject unsafe link/path escapes; S3 uses only the configured prefix and conditional exact-key operations.

Use two durable forced-RLS tables: publication_attempts keyed by workspace plus opaque attempt ID (identity, object key, state, lease/claim/generation, exact reference/digests/lengths), and publication_idempotency keyed by workspace/kind/idempotency_key (permanent request identity and canonical admitted response/reference). An idempotency row maps to a canonical attempt/version; different keys can alias an already committed exact version without violating attempt uniqueness. Catalog's existing workspace/kind/id/version primary key arbitrates immutable versions. Serialize version admission using a transaction-scoped lock or dedicated canonical version row, never a process mutex. Idempotency identity comprises descriptor ID/version and exact original bytes; max_bytes changes only whether the complete saved response can be returned.

Validate all input/evidence, serialize the complete canonical receipt and enforce the effective response budget before any attempt, ledger, object, catalog or outbox mutation. Then reserve an identity/owned attempt in a short principal-bound transaction; stage exact bytes outside long SQL locks; then atomically admit catalog/original-byte/object-reference/ledger response plus exactly one version_published outbox event, using WithTenantPrincipal and AppendEventInTransaction with a final current-policy fence. Same key/identity returns saved bytes; changed identity conflicts. Same version/bytes under another key returns existing admission plus an alias ledger row and no event; changed bytes or a revoked version conflicts. Retain identity/result records for the immutable version/revocation lifetime, without a short TTL.

Selected source retention: staged upload lease/retention 24 hours from database time; committed object and identity lifetime indefinite while their catalog/revocation records exist. Same-identity authorized retries may renew an unclaimed staged lease. Cleanup claim lease is five minutes. A deleting claim blocks admission/renewal; its generation token fences stale workers. SQL faults/ambiguous commits or cancellation retain an owned attempt for retry/reconciliation, never a guessed compensating deletion.

Reconciliation uses explicit configured current maintenance principals per workspace, no global workspace enumeration. Poll at one minute, at most 20 attempts per workspace per pass, with configured request deadline; current authority is refreshed each pass. Claim expired staged attempts with row locks/SKIP LOCKED, verify no committed catalog/reference points to the exact owned key, commit a deleting lease/generation, then delete only that key and mark completion in a second transaction. A failed delete retains retryable state; an interrupted claimed delete resumes after lease expiry; not-found counts as success only for the same owned claim. Permanent identity and retired-object-key tombstones remain after physical deletion; retries cannot reuse an old physical key or use the idempotency key for changed bytes. A same-identity retry after deletion creates a new opaque attempt/key and updates the ledger only through the fenced state transition. Cleanup periodically revisits retired-key tombstones with a fair bounded cursor to catch late/ambiguous object PUT completion; a client timeout is not proof that the backend stopped writing. A stale upload can never be admitted or rebound, and its retired key remains owned and deletable without touching any current committed key. Publisher and cleaner must lock/fence the same attempt state. Never delete global legacy/shared digest objects, committed keys, foreign tenant keys or an object lacking a durable owned row.

## Internal lane handoff contract

The coordinator owns composition and shared interfaces. Freeze these publication-specific port semantics before splitting PUBLISH.1 work:

| Boundary | Chosen semantics |
|---|---|
| V2 publisher | `PublishV2(ctx, principal, kind, rawEnvelope) -> PublicationResult{Body []byte, Created bool, ArtifactDigest, ManifestDigest, PackageDigest}`; only publisher prepares/persists a canonical complete receipt and enforces parsed client/server budget before mutation. Created selects 201/200 and is not serialized into Body. |
| V2 reader | `ReadV2(ctx, principal, exactRef, maxBytes, packageBody bool) -> PublicationRead{Body []byte, ContentType, ArtifactDigest, BodyDigest, ManifestDigest, PackageDigest}`; authorizes current catalog-read policy, checks tenant/revocation and complete body size/digests. Missing optional skill digests for typed kinds are absent, never invented. |
| Owned stage/cleanup | Storage reserves/loads an owned attempt through the current principal and database fencing before generating backend keys. Stage/Open use that durable handle; DeleteClaimed takes a storage-created handle with current attempt/state/generation, rechecks its durable claim, and deletes only its exact key. No raw-key REST or generic caller delete interface. Retired physical keys are never reused. |
| Trusted evidence | Typed `PublicationAdmissionEvidence` binds exact workspace/kind/id/version/raw artifact SHA, reviewer/source/retained capture digest+bytes/time/license/rights, optional source-origin publisher, exact approved support_state and conformance fixture/executor/result pins. It is decoded from a trusted approved review row, not request JSON. Unknown/missing fields or bindings fail closed. |
| Offline binding verifier | Qualified `VerifyPublicationBinding(ctx, exactRecords, evidence, goldenBytes) -> error` with actual retained-byte/hash and at least five executed offline cases. The configured verifier identifies its exact adapter revision; no external/provider calls or blanket successful fake. Unavailable adapter evidence denies binding admission. |

Implementation workers may add concrete structs/interfaces preserving these semantics under coordinator ownership; any semantic change returns to independent interface review. PUBLISH.2 acceptance uses an actual qualified local offline verifier and explicitly owned synthetic capture/license fixtures to exercise source behavior; those fixtures never qualify real providers. Evidence configuration defaults deny synthetic records in production. Existing record-to-pin behavior and current authorization code are regression inputs, not already-qualified new mappings.

Source quota defaults: at most 64 uncommitted attempts and 100,000 permanent idempotency keys per workspace, checked transactionally before reserving a new identity. Quota exhaustion returns bounded retryable 503 without mutation; existing valid replay remains available. No short TTL/eviction removes identity guarantees. Configured catalog limits remain separate. These are source resource bounds, not an AWS storage/spend approval.

## Additive source lock migration

The frozen v1 lock pins the complete catalog port source file as well as wire
contracts. V2's approved catalog projection adds DocumentDigest, PackageDigest,
ObjectKey and ArtifactSize to the internal record. The explicit
[source amendment](../../contracts/registry/v2/source-amendments.json) pins both
the original v1 hash and current source hash and the exact additive fragment.
The normal freeze gate reconstructs and verifies the complete original file;
changes outside that fragment, stale hashes, duplicate/unmatched amendments and
wire-file amendments fail. V1 schemas, routes, dependency locks and lock bytes
remain unchanged. This is source compatibility, not deployment migration.
