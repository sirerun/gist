# PUBLISH.0 typed artifacts and consumer preflight

Date: 2026-10-09  
Scope: source/design qualification only. No handler, provider, credential, infrastructure, or deployment qualification is asserted.

## Finding

The current publisher is not a typed publisher. `hosted/internal/rest/publish.go:publish` reads the request as opaque bytes and calls the shared `Publisher.Publish`; `hosted/internal/app/adapters.go:publisher.Publish` always calls `packages.ReadArchive` and `packages.Validate`, irrespective of `kind`. The validator requires `manifest.json` and `SKILL.md` (`hosted/internal/packages/validate.go:Validate`). Therefore a capability, tool, provider, binding, or taxonomy JSON document cannot currently be published through the actual path. Route tests and seed loaders do not close this gap.

The read side expects kind-specific JSON metadata: `hosted/internal/rest/catalog.go:getArtifact` writes `CatalogRecord.Metadata` as JSON; `hosted/internal/storage/postgres.go:Get` stores/returns that field as bytes; `hosted/internal/app/canonical_adapter.go` and `hosted/internal/resolution/resolve.go` decode skill, capability, provider, and binding records. The present ZIP publisher instead stores manifest bytes as metadata, puts the archive digest in `CatalogRecord.Digest`, and the manifest-byte digest in `ManifestDigest`. This means the current skill publication shape is not even the same document shape as the current resolver expects for a skill. The proposed v2 profile must explicitly adapt storage/readback and resolver consumers; it cannot claim v1 consumer compatibility merely because the existing `CatalogRecord` fields can hold hashes.

## Recommended frozen predicates

Common admission applies before kind-specific validation. Decode the envelope and every nested object with a strict token parser that rejects invalid UTF-8, duplicate decoded member names (including escaped-equivalent names), case variants of declared field names, unknown fields, multiple/trailing JSON values, and malformed surrogate sequences. Enforce body size before parsing, encoded and decoded ZIP limits before extraction, expanded byte/file limits during extraction, then effective successful response budget before object staging or DB/outbox mutation. Authentication must provide workspace, subject, issuer, and current policy generation; none is accepted from request fields. Refresh membership and active role for each publish and again before returning an idempotent prior result. Only an active current workspace maintainer with `catalog:publish` may publish. Confine IDs and all referenced artifact namespaces to that workspace; reject tenant/publisher fields in submitted documents.

For JSON documents, preserve the exact `json.RawMessage` value span: after the opening value's leading JSON whitespace through its final token byte, excluding whitespace before the value and trailing transport whitespace. Hash and persist those original bytes; validation operates on a separate copy. A scanner must identify the exact span before unmarshalling, validate UTF-8, recursively reject duplicate keys at every depth, and require EOF after permitted outer whitespace. Never marshal the decoded value to calculate an immutable artifact digest and never use PostgreSQL JSONB output as source bytes. Any whitespace or member-order change inside the value is a changed identity. Request-level duplicate checks alone are inadequate.

The envelope descriptor is `{id,version,document}` for non-skills. Require byte-exact string agreement between descriptor and document identity fields. Capability, tool, and binding documents carry `id` and `version`; taxonomy carries `id` and `edition`, so require `descriptor.version == document.edition`. Provider v1 has `id` but no version: match `id`, use the outer descriptor version as registry version, and do not inject a version into the provider document. IDs must pass the existing lower-case artifact-ID grammar (including namespace prefix), be bounded, and have no whitespace/control characters or traversal. Namespace policy must be explicit: publishers may mint only IDs in namespaces registered to their workspace; cross-namespace references in skills/bindings must resolve to exact versions within that workspace and may not create or shadow another publisher's ID. Recheck the namespace owner/current maintainer relationship on replay.

## Digest and consumer mapping

`ports.CatalogRecord` has only `Digest`, `ManifestDigest`, and `Metadata` (`hosted/internal/ports/catalog.go`). `catalog_versions` and `Postgres.Get` persist two digest columns and metadata. For v2, `Digest` must continue to mean immutable transferred blob digest (ZIP for skill, exact JSON value otherwise), because `storage.ObjectStore` resolves the object through this catalog digest (`hosted/internal/storage/objects.go`). `ManifestDigest` can only mean exact skill manifest bytes; current schema's non-null columns and resolution pins assume both digest values exist. A schema/migration/interface change is needed before non-skill publication can fit safely: either make manifest digest nullable and name it as optional in API/pins, or add a separately named document digest column and preserve `Digest` for object bytes. Do not put the taxonomy/provider/tool embedded digest or inventory closure in the manifest column.

The inventory closure digest remains in skill manifest `package_digest` and an explicit v2 `package_digest` response/header. `CatalogRecord` has no package digest field, so any consumer needing it must read the manifest or gain a named field; never overload `Digest`. `artifact_digest` hashes what v2 transfers as its artifact blob. `manifest_digest` hashes exact detached manifest bytes. `package_digest` hashes canonical sorted inventory records through `contract.PackageDigest`. Embedded provider capture, tool capture, and binding fixture digests retain their own byte domain. Readback must assert all mappings by rehashing the returned body/archive and, for skills, the returned manifest and inventory.

Affected contracts/interfaces: new v2 publish and exact-read route/schema; `rest.Publisher.Publish(context.Context, ports.Principal, ports.ArtifactKind, []byte) ([]byte,error)` (currently raw bytes in and opaque JSON bytes out); `ports.CatalogRecord`/`ArtifactPin`; publisher app adapter; storage catalog SQL and nullable digest representation; object-store `Put`/`Open` binding; REST catalog exact read/package read; resolver skill and binding decode/pin path; seed/catalog import boundary; SDK/client response digest interpretation. `GET /v1` read and resolver behavior must be regression-tested with existing admitted skill/capability/provider/binding fixtures before any compatibility claim. Taxonomy has a separate `TaxonomyStore` keyed by workspace/id/version and edition/list routes, not ordinary `CatalogRecord` retrieval. Provider exact-get is absent from current v1 routes. A frozen-v1 raw-ZIP publisher may be described as historical implementation behavior only; there is no supportable claim that it accepts canonical typed JSON, and no blanket claim that all existing v1 reads/resolution remain compatible with v2 until digest/metadata mappings are proven.

## Isolated bounded implementation write set

Keep implementation isolated to `contracts/registry/v2/**`, v2 OpenAPI/routes and `hosted/internal/rest/{publish,router,catalog}.go`, strict JSON span/duplicate parser and typed validators in new contract files, `hosted/internal/app/adapters.go` publisher split, `hosted/internal/ports/catalog.go`/publisher interfaces, `hosted/internal/storage/{postgres,objects,taxonomies}.go` plus a forward-only migration, and focused tests/fixtures under corresponding contract/rest/app/storage directories. SDK paths may be touched only after inventorying actual exported publisher/read clients; no consumer-wide rewrite is implied. Do not edit frozen `contracts/registry/v1/**`, this plan, seed data, unrelated resolver behavior, provider clients, or deployment/IaC. Staging must gain tenant-safe ownership, retention and reconciliation before production admission; current integration evidence explicitly shows failed DB/outbox publication can leave an unbound private staged digest (`core_publication_transaction_integration_test.go`).
