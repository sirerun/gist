It says HTTP 200 can still contain per-URL failures or no successful results. The current [credits page](https://docs.tavily.com/documentation/api-credits) prices five successful Basic extractions at one credit and five Advanced extractions at two credits; it lists pay-as-you-go at $0.008 per credit. The public docs show no immutable API/schema revision or versioned path. The Treg catalog represents `urls` as a required string array; the current Tavily request example shows `urls` as a string while its prose allows a batch. Exact serialization and a version-pinned request/response JSON Schema therefore remain unqualified. No action was called to resolve this discrepancy.

## Proposed narrow interface and write set

If separately admitted after the gates below, keep this as a caller-executed, exact operation. Gist records the capability; it does not proxy or execute it. Proposed caller-side request mapping is one owner-selected public HTTPS README URL, `extract_depth=basic`, `format=markdown`, `include_images=false`, and `include_favicon=false`; omit query/chunks and all unapproved fields. Do not permit arbitrary destinations, additional URLs, caller-supplied authorization headers, fallback providers, or generic provider dispatch. Reject private/reserved destinations and unsafe redirects before dispatch. Model the operation as an external content fetch with a vendor request and billable result, not as a no-effect local read. Preserve per-URL `results`/`failed_results` and do not treat an empty `results` array as successful content.

The prospective T-GR-TREG.1 ownership stays within newly allocated `catalog/registry/captures/treg-*` and `catalog/registry/packages/treg-*` artifacts plus separately assigned capture/conformance tests. The exact filenames and test paths still need allocation before implementation. Shared `tools`, `providers`, `bindings`, and `capabilities` indexes belong to the integrator. The acceptance tests should reject unpinned or drifted schemas, string/array mapping ambiguity, extra body fields, multiple or disallowed destinations, unknown pricing, any fallback/overflow, changed binding/digest, and missing/partial failure evidence; and should verify the exact artifact/package digests and caller-execution requirement. No plan, contract, application, index, or artifact file was changed in this preflight.

## Required decisions and evidence still missing

- **Schema/version/provenance:** the public Extract docs and catalog provide useful field descriptions but no immutable API version, canonical JSON Schema, or pinned revision. Confirm exact Treg-to-Tavily request mapping, complete success/error response schema, and source provenance with a version or immutable capture basis; metadata examples alone do not settle the `urls` representation.
- **Account, auth, route, and scope:** Tavily documents Bearer authentication. The actual caller-owned Tavily or Treg route, account/key custodian, downstream-use permission, and least-privilege boundary are unselected. Tavily's [current platform terms](https://www.tavily.com/terms) say API/Agent Key use is for the customer's internal business purposes and that a key may not be shared with third parties without prior written consent. The owner must qualify an authorized caller-owned route or applicable written permission. Never place a shared credential in a public Gist artifact.
- **Cost and upper bound:** for one successful URL, the documented current schedule implies $0.0016 Basic or $0.0032 Advanced at the catalog's stated pay-as-you-go conversion. The candidate uses Basic and one URL, but the actual account plan, Treg shared-key versus caller-owned-key billing route, approved account, and reservation/aggregate bound are unknown. The existing proposed $0.10 per-call, $1 combined, five-calls-per-provider per rolling 24 hours, 24-hour expiry remains unapproved. Do not treat advertised/free credits as spending authority.
- **Content license and retention:** the endpoint catalog has no redistribution-license field. The reviewed terms assign the customer rights in its input and grant Tavily broad rights to process that input; they do not establish a license for third-party page content returned by Extract or a right for Gist to republish it. The [privacy policy](https://www.tavily.com/privacy) gives general purpose-based retention criteria, not an Extract request/response retention or deletion window. Obtain owner/legal approval for the selected source's license and downstream storage/display, the API terms and any order form, permitted input handling, retention, deletion, and third-party processing. Do not infer zero retention.
- **Exact recipient/task:** the existing owner receipt proposes at most one public README URL but says no exact URL or provider account was selected. The founder/coordinator must select the task and exact public target, confirm permission to fetch and retain its content, and approve provider and content-processing scope before capture or any later call.

These blockers leave T-GR-TREG.0 open and keep the provider candidate `catalog_only`. They do not prevent unrelated source-only lanes. No schema was guessed, no executable artifact was admitted, and no provider call or spend was made.
